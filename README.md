# Туман (TMN/1)

Транспорт поверх настоящего TLS 1.3 для обхода DPI/ТСПУ. Не «новый шифр» и не «новый handshake» — надстройка над TLS: свой кадровый протокол, мультиплексирование, шейпинг формы трафика и сервер, неотличимый от обычного сайта.

> Статус: **экспериментальный**, этап 3 из 5. Приватное использование, не продукт.

## Зачем

Блокировки 2026 года перестали быть «списками запрещённых SNI». Основное — поведенческий анализ: сколько соединений, сколько байт, как долго, в каком соотношении. Поэтому:

- **свой шифр не нужен**: TLS 1.3 уже даёт неотличимый от случайного шифротекст, а его цензор обязан пропускать;
- **нужен слой формы**: подгонка профиля трафика под реальный класс нагрузки, а не случайный шум;
- **нужна политика соединений**: одна сессия или пул, ротация адресов, лимиты объёма;
- **нужна инфраструктура**: свой домен и сертификат вместо чужого SNI, чтобы ASN сходился.

## Архитектура

```
приложение → SOCKS5 → [TLS 1.3 + кадры TMN/1] → tmns → интернет
                │                                        │
             shaper (профили)                    сайт-прикрытие
             route (split-tunnel)                rate-limit
             endpoint pool (4 TCP)
```

| Слой | Пакет | Что делает |
|---|---|---|
| Кадр | `proto/` | 8-байтовый заголовок, AUTH по HMAC+TLS-exporter, адресный блок |
| Мультиплекс | `mux/` | потоки в одном TCP: окна, WU, PING, Reset |
| Форма | `shaper/` | профили `off/browse/video/bulk/voice`: паддинг, коалесинг, pacing |
| Маршрут | `route/` | split-tunnel по домену/CIDR/порту |
| Клиент | `cmd/tmnc` | SOCKS5, пул TCP, health ендпоинтов, автопереключение |
| Сервер | `cmd/tmns` | TLS 1.3, фолбэк на сайт-прикрытие, egress, anti-probing |

## Что измерено

Все цифры — на реальном канале и реальном VPS, не в теории.

| Метрика | Значение |
|---|---|
| Потолок маршрута (iperf3, 8 потоков) | **540 Мбит/с** вниз, 757 вверх |
| Один TCP до VPS | 227 Мбит/с |
| Наш туннель, 4 TCP в пуле | **422 Мбит/с** (161 → 422, ×2.6) |
| Reality в том же окне | 539 Мбит/с |
| Наш туннель, loopback | **2062 Мбит/с** на поток |
| Затраты на кадрирование | 36 нс, 0 аллокаций |
| Оверхед шейпера `browse` | +3.6 нс на запись, паддинг 0.36 % |

Честная оговорка: 800 Мбит/с на этом маршруте недостижимы физически — канал даёт 540. Вверх гигабит реален.

## UDP

SOCKS5 `UDP ASSOCIATE` (RFC 1928 §7): датаграммы идут в обычном mux-потоке,
помеченном `FlagUDP`, кадрами «u16 длина + данные». Протокол не менялся, поэтому
TCP-путь остаётся прежним; сервер открывает по одному UDP-сокету на цель и
применяет к ней ту же egress-политику и тот же DoH-резолвер, что и к TCP — иначе
UDP стал бы обходом SSRF-фильтра.

| Проверка | Значение |
|---|---|
| DNS через туннель (`1.1.1.1:53`) | 46–53 мс, `rcode=0`, 2 ответа |
| Потолок датаграммы | 8 КиБ (QUIC ~1350 байт), сверх — поток рвётся, сессия живёт |
| Фрагменты (`FRAG≠0`) | отбрасываются, не склеиваются |
| Чужой источник на порту ассоциации | молча игнорируется |

Маршрутная таблица применяется и к UDP: `block` закрывает цель для датаграмм,
`direct` уводит мимо туннеля. Ассоциация умирает вместе с TCP-контролем, как
требует RFC; молчание цели 60 с закрывает её поток.

## QUIC

Второй носитель того же туннеля: список серверов принимает `quic://`, сервер
поднимает UDP-ендпоинт рядом с TCP.

```toml
# сервер
listen      = "0.0.0.0:443"   # TCP: сайт-прикрытие и TLS-носитель
quic_listen = "0.0.0.0:443"   # UDP: тот же порт, отдельный транспорт

# клиент
servers = ["tuman.example:443", "quic://tuman.example:443"]
```

TLS 1.3 живёт внутри QUIC, поэтому второго TLS нет: mux идёт прямо в потоке,
привязку к каналу даёт AUTH v2 (X25519 — exporter не нужен). Одна сессия = одно
QUIC-соединение и один поток. Health-лестница та же: ендпоинт с `quic://` —
такой же член пула, при отказе уходим на следующий и возвращаемся, когда оживёт.

**Зачем, если это не быстрее.** Скорость не цель — на чистом канале выигрыша
нет. Цель: второй транспорт в пуле (TCP:443 душат — идём по UDP), и отсутствие
блокировки начала очереди на уровне потока, когда канал теряет пакеты.

**Чего здесь нет.** Сайта-прикрытия на QUIC-ендпоинте быть не может: он
объявляет один ALPN (`tuman`), чужой клиент получает отказ на handshake. Не
сделана миграция соединения (наш mux по-прежнему переустанавливает сессию) и не
сделан браузерный отпечаток QUIC-Initial. Шейпер (`profile`) на этом пути не
навешен.

| Проверка (loopback, TLS-серт самоподписанный) | Значение |
|---|---|
| 12 запросов по 200 КБ через QUIC | 0 отказов (и 0 напрямую) |
| 50 МБ через QUIC vs напрямую | 20.7 с vs 20.4 с — оверхед ~1.4 % |
| 1 МБ эхо через mux поверх QUIC | байт в байт |
| Неверный ключ | поток закрыт, в счётчик туннеля не попал |

## TUN

Режим для приложений, которые не умеют SOCKS5: L3-устройство на обеих
сторонах, IP-пакеты едут одним mux-потоком (`FlagIP`, кадры «u16 длина +
пакет»). TCP, UDP, ICMP и сборку потока делает стек ядра — как в WireGuard, а
не свой userspace-стек, поэтому здесь нет ни NAT-таблиц, ни TCP-состояния.

```toml
# сервер: /etc/tmn/tmns.toml
tun      = "tuman0"        # имя устройства
tun_addr = "10.66.0.1/24"  # адрес, по которому клиенты видят сервер

# клиент: tmnc.toml
tun      = "tuman0"
tun_addr = "10.66.0.2/24"
```

MTU 1398 = 1400 (максимальная нагрузка кадра) − 2 байта длины: пакет ложится в
один кадр. Устройство на Linux — `/dev/net/tun` (нужен CAP_NET_ADMIN), на
Windows — Wintun (нужны права администратора и `wintun.dll` рядом с `tmnc.exe`;
взять на wintun.net).

**Маршруты — на операторе.** Туннель не переписывает таблицу маршрутов: иначе
первый же `default` через устройство увёл бы в него соединение с самим сервером.
Что нужно на клиенте:

```bash
# Linux: сервер напрямую, остальное в туннель
ip route add <server-ip>/32 via <gw>            # обход до сервера
ip route add default dev tuman0
# Windows
route add <server-ip> mask 255.255.255.255 <gw>
route add 0.0.0.0 mask 0.0.0.0 0.0.0.0 if <idx tuman0>
```

На сервере — `net.ipv4.ip_forward=1` и MASQUERADE для подсети туннеля, если
клиенты должны выходить в интернет через него.

| Проверка (Windows, wintun 0.14) | Значение |
|---|---|
| ICMP через туннель, 10 пакетов по 1328 Б | 13280 Б из 13280, потери 0 |
| UDP 1398 Б, 150 МБ, 2 потока | 3.2 Гбит/с предложено, 144 МБ доставлено |
| Реконнект после падения процесса | адаптер переиспользуется, orphan удаляется драйвером |

Свойства: один поток-владелец устройства на сервере (второй клиент получает
отказ, а не половину пакетов), backpressure через кольцо драйвера (4 МиБ) вместо
очереди в Go — со `drop` под нагрузкой терялось 97 % пакетов.

Разделения трафика по правилам в TUN-режиме пока нет: что попало в устройство,
то идёт в туннель — режется маршрутами ОС.

## Почему это не «ещё один Xray»

Reality заканчивает TLS-сессию на настоящем чужом сайте — блестящий трюк, но IP наш, а ASN чужой, и это видно. XHTTP гоняет туннель в HTTP/2 к настоящему сайту — но платит оверхедом и ловится на параллельных соединениях.

Здесь: **свой домен, свой сертификат, свой сайт-прикрытие**. Неавторизованный клиент видит нормальный веб-сервер: `200` с HTML на `/`, `404` на остальное, ответ на невалидный AUTH через 2 секунды как idle keep-alive, rate-limit с честной 429-страницей. Ни одного байта, по которому можно понять, что это прокси.

## Быстрый старт

```bash
go build ./cmd/tmns ./cmd/tmnc
```

Зависимость ровно одна — `refraction-networking/utls` для браузерного
отпечатка. Она лежит в `vendor/`, поэтому сборка не требует сети (на VPS
`go build` тоже работает без прокси).

Сервер (`/etc/tmn/tmns.toml`):
```toml
listen   = "0.0.0.0:443"
cert     = "/etc/tmn/cert.pem"
key      = "/etc/tmn/key.pem"
psk_file = "/etc/tmn/psk"
cover_dir = "/var/www/tmn"
profile  = "browse"
dns      = "https://1.1.1.1/dns-query"   # пусто/«system» — системный резолвер
```

Клиент (`tmnc.toml`):
```toml
servers     = ["vps1.example.net:443", "vps2.example.net:443"]
sni         = "www.example.net"
psk_file    = "/etc/tmnc/psk"
socks_listen = "127.0.0.1:1080"
conns       = 4
routes_file = "examples/routes-ru.toml"
profile     = "browse"
auth_v2     = true          # MAC сервера + ключ на сессию; обязателен с fingerprint
fingerprint = "chrome"      # off | chrome | firefox | safari | golang
```
