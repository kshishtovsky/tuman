## 1. Что нужно замерить в первую очередь (на реальном канале, 30 минут)

```bash
# 1. RTT/потери/маршрут до Хельсинки, 20 пакетов
mtr -rwzc 20 <VPS_IP>

# 2. Потолок VPS: сервер
iperf3 -s -p 5201
# клиент, 30 c, 4 потока, оба направления
iperf3 -c <VPS_IP> -p 5201 -t 30 -P 4
iperf3 -c <VPS_IP> -p 5201 -t 30 -P 4 -R

# 3. Один поток (важнее всего: NFR-1)
iperf3 -c <VPS_IP> -p 5201 -t 30

# 4. Жив ли UDP до VPS (без этого QUIC-режим мёртв)
iperf3 -c <VPS_IP> -p 5201 -u -b 100M -t 10

# 5. Троттлинг Cloudflare-пути (контроль C)
curl -o /dev/null -w '%{speed_download}\n' https://speed.cloudflare.com/__down?bytes=50000000
```

Фиксируем в `docs/measurements-2026-10.md`: скорость 1/4 потока, RTT min/avg/max, потери, поведение UDP, скорость Cloudflare.

## 2. Стенд: эмулятор DPI

Почему не «попробовать на живом ТСПУ»: живой ТСПУ не даёт воспроизводимости и не объясняет, какое правило сработало. Нужен локальный эмулятор с 5 правилами.

```
[client netns] --- veth --- [router netns: tc netem + nfqueue DPI] --- veth --- [server netns]
```

Инструменты: `iproute2` (netns, tc), `nftables` + `NFQUEUE`, Python-скрипт на `nfnetlink_queue` (или Go), `tcpdump`. Всё в одном контейнере `--privileged --cap-add=NET_ADMIN`.

### Правила эмулятора (соответствуют слоям из research)

| # | Правило | Как детектим | Действие |
|---|---|---|---|
| R1 | Сигнатура | первые 32 байта потока: WG 148-байтный handshake, SS, OpenVPN opcode | drop |
| R2 | JA3-белый список | парсинг ClientHello, JA3 по таблице Chrome/Safari/Firefox | drop при неизвестном |
| R3 | TLS-in-TLS | после handshake: запись < 700 Б в первых 4 КБ, затем запись > 1200 Б в течение 50 мс | пометить (score +1) |
| R4 | Поведение | > 3 TLS-соединений к одной паре (IP, SNI) за 60 с | заморозка 120 с |
| R5 | Полоса UDP | доля UDP > 40 % от полосы за 10 с | троттлинг до 5 Мбит/с |

Метрика: по каждому кандидату — `score` (сколько правил сработало) и время до первого срабатывания.

### Команды каркаса

```bash
ip netns add cli && ip netns add srv && ip netns add rtr
ip link add vc type veth peer name vr1 && ip link set vc netns cli && ip link set vr1 netns rtr
ip link add vs type veth peer name vr2 && ip link set vs netns srv && ip link set vr2 netns rtr
# адреса, маршруты, forward...
ip netns exec rtr tc qdisc add dev vr2 root netem delay 15ms loss 0.2% rate 1gbit
# DPI: nft rule с queue num 0 bypass, обработчик в userspace
ip netns exec rtr nft add rule inet filter forward tcp dport 443 queue num 0 bypass
```

Обработчик получает пакеты, собирает поток, ведёт состояние (5-tuple → вердикт), умеет `drop`, `accept`, «заморозить» (перестать пропускать 120 с).

## 3. Эксперименты (по порядку, каждый — с критерием)

| ID | Гипотеза | Метод | Критерий прохода |
|---|---|---|---|
| E1 | Крипто-слой не узкое место | iperf3 через наш RAW-прототип в netns | ≥ 700 Мбит/с, CPU ≤ 50 % ядра |
| E2 | WEB-мимикрия не убивает скорость | тот же поток через HTTP/2-инкапсуляцию | падение ≤ 10 % vs E1 |
| E3 | Паддинг первых 64 КБ снимает R3 | прогон через эмулятор с R3 | score 0 на R3, доп. трафик ≤ 20 % |
| E4 | Одна сессия обходит R4 | 10 параллельных загрузок в одной сессии | R4 не срабатывает; vs пул соединений — срабатывает |
| E5 | TCP-путь даёт приемлемый голос | UDP-поток поверх TCP-сессии, эмуляция 2 % потерь | jitter p95 ≤ 30 мс, потерь кадров < 1 % |
| E6 | QUIC-путь быстрее на плохом канале | netem 2 % потерь + 3 % reorder | QUIC ≥ 1.3× TCP по throughput |
| E7 | Активное зондирование не отличает сервер | 20 проб: свой SNI, чужой SNI, без SNI, невалидный AUTH | все ответы как у обычного сайта, ни одного TLS alert |
| E8 | 30-минутная сессия не деградирует | видео 20 Мбит/с + bulk 300 Мбит/с, 30 мин | нет роста RTT > 20 %, нет разрывов |

Порядок: E1 → E3 → E4 → E2 → E7 → E5 → E6 → E8. Первые три отвечают на «живёт ли идея», остальные — на «какой ценой».

## 4. Прототип для экспериментов (минимум кода)

Не полноценный клиент. Один Go-бинарь, две подкоманды:
- `tmn bench -mode raw|web -pad on|off` — гоняет поток через TLS к серверу и печатает throughput/CPU;
- `tmn probe -host X` — набор проб активного зондирования и их результат.

Этого хватает для E1–E4, E7. Полный mux/роутер/шейпер — этап 2, после подтверждения чисел.

Правило: прототип пишется в `E:\PET\tuman\proto\` и не является кодом продукта (никаких обещаний совместимости).
