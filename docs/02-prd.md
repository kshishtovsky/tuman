# 02. PRD: транспорт «Туман» (TMN/1)

Версия: 0.1 (этап 1). Владелец: автор. Статус: на ревью.
Связанные документы: `01-research-dpi-2026.md`, `03-system-design.md`, `04-lab-plan.md`.

---

## 1. Контекст и проблема

Пользователь в РФ, домашний канал 1 Гбит/с (реально 800–900 Мбит/с в обе стороны). Есть VPS в Хельсинки с панелью и работающими VLESS/Reality/XHTTP/Hysteria2. Проблемы, которые не решает текущий набор:
1. Волны блокировок 2026 бьют по «хорошо настроенным» Reality/XHTTP серверам (поведение + фингерпринт).
2. Сервисы, блокирующие РФ-адреса, требуют выхода в ЕС и приличной репутации IP.
3. Мобильный сценарий (UDP-голос Discord, троттлинг UDP, белые списки).
4. Нет единого поведения «что включить, когда сломалось» — переключение руками.

## 2. Цели (outcomes, не фичи)

| ID | Цель | Метрика |
|----|------|---------|
| G1 | Не терять скорость | **пересмотрено по iperf3 29.10.2026: потолок маршрута вниз = 540 Мбит/с** (8 потоков), вверх 757. Цель: ≥ 420 Мбит/с на 4 параллельных загрузках (паритет с Reality 539, наш пул даёт 620), одиночный поток ≥ 200 |
| G2 | Не добавлять заметный пинг | overhead туннеля ≤ 3 мс сверх RTT(клиент↔Хельсинки); игры/голос — мимо туннеля |
| G3 | Переживать блокировку сервера | время до детекта ≫ время до восстановления: восстановление ≤ 60 с без действий руками (авто-переключение ендпоинта/транспорта). Смена адреса ≤ 5 минут, ≤ €5 |
| G4 | Не палиться | сервер проходит активное зондирование как обычный сайт; профиль трафика не выделяется на фоне эталона. Целевой порог объёма: **≥ 50 ГБ/сутки на адрес без деградации** (полевой факт владельца), ротация — при 150 ГБ |
| G5 | Работать там, где UDP закрыт | полный функционал (включая голос) по TCP-пути |
| G6 | Обслуживать 1–5 человек без админства | конфиг генерируется, обновляется, деградация видна в логе |

## 3. Non-goals

- Публичный/коммерческий сервис, продажа доступа, реклама. (Правовой риск в РФ: предоставление доступа к заблокированным ресурсам как услуга.)
- Кроссплатформенный «красивый» клиент с магазинами приложений.
- Собственный крипто-примитив или собственный handshake.
- Обход белых списков на домашнем интернете (архитектурно заложим смену ендпоинтов, но гарантий нет).
- Мультирегион, балансировка, панель с биллингом.

## 4. Персоны и сценарии (JTBD)

- **P1 Владелец (десктоп Windows + Android).** «Хочу включить и чтобы YouTube 4K, Gemini и Medium работали на полной скорости, без ебли с конфигами».
- **P2 Близкий человек (телефон, не технарь).** «Одна кнопка. Если не работает — само починилось».
- **P3 Геймер/голос.** «Discord-голос без лагов, ping в игре не вырос».

Сценарии: S1 просмотр 4K (20–40 Мбит/с, длинная сессия), S2 звонок Discord (UDP, jitter < 30 мс), S3 скачивание 20 ГБ (bulk, длится час), S4 «сайт с капчей» (нужна репутация IP), S5 мобильный интернет в поездке (потери, NAT, смена сети).

## 5. Функциональные требования

| ID | Требование | Приёмка |
|----|-----------|---------|
| FR-1 | TUN-режим (весь трафик) и proxy-режим (SOCKS5/HTTP) | Оба режима работают на Win/Android |
| FR-2 | Split-tunneling по приложениям, доменам, IP-спискам, geo | РФ-сайты и игры идут напрямую; проверяется по логам маршрутизации |
| FR-3 | Перенос TCP и UDP (включая голос) | Discord-звонок 10 мин без разрывов; `[ЗАМЕР]` jitter |
| FR-4 | Авто-выбор транспорта: TCP-TLS → QUIC → CDN/фолбэк | При блокировке порта 443/tcp доступ восстанавливается ≤ 60 с |
| FR-5 | Несколько ендпоинтов (≥2 ASN), health-check, авто-ротация | Убийство одного IP не рвёт сессию дольше 60 с |
| FR-6 | Маскировка под настоящий сайт: свой домен + валидный серт + сайт-прикрытие | Активное зондирование возвращает 200 и HTML сайта; curl с любым SNI/Host ведёт себя как обычный сервер |
| FR-7 | Аутентификация без ответа чужим | Соединение без валидного ключа обрабатывается как обычный HTTPS-визит, никаких RST/ошибок протокола |
| FR-8 | Шейпинг трафика под выбранный профиль (browsing / video / bulk) | Профиль выбирается политикой; `[ЗАМЕР]` статистическая близость к эталону |
| FR-9 | DoH/DoT внутри туннеля, без утечек DNS | dnsleak-тест: все запросы уходят через VPS |
| FR-10 | Опциональный «жилой» егресс (WARP-подобный) для капча-сервисов | Medium/AI-сервисы открываются без 403 в 9/10 попыток |
| FR-11 | Диагностика: почему не работает (слой L1–L5) | Один экран/лог: какой слой подозревается, что сделано |
| FR-12 | Ротация ключей/подписок без переустановки | Обновление конфига на телефоне без ручных действий |
| FR-13 | Совместимость с существующей панелью | Не ломает текущие Reality/XHTTP/Hysteria2 профили; новый сервер ставится рядом |

## 6. Нефункциональные требования

| ID | Требование | Бюджет/приёмка |
|----|-----------|----------------|
| NFR-1 | Пропускная способность, 1 поток | ≥ 700 Мбит/с на канале 800–900, RTT до HEL `[ЗАМЕР]` |
| NFR-2 | Пропускная способность, 10 потоков | ≥ 850 Мбит/с суммарно, CPU VPS ≤ 70 % одного ядра |
| NFR-3 | Добавленный RTT | ≤ RTT(клиент↔HEL) + 3 мс; без доп. RTT на handshake (0-RTT/сессионный resumption) |
| NFR-4 | CPU клиента при 800 Мбит/с | ≤ 50 % одного ядра (замерено: TLS 1.3 даёт 6.1 Гбит/с ⇒ запас 7×) |
| NFR-5 | Память/батарея на мобильном | ≤ 150 МБ RSS, ≤ 6 %/час активного видео |
| NFR-6 | Устойчивость к потерям 2 % | ≥ 60 % от скорости без потерь (BBR-класс CC) |
| NFR-7 | Время установления соединения | ≤ 1 RTT (resumption), ≤ 2 RTT (первый запуск) |
| NFR-8 | Незаметность handshake | профиль первых 8 записей статистически не отличим от эталона `[ЗАМЕР]` |
| NFR-9 | Отсутствие TLS-in-TLS сигнатуры | ни одна запись ≤ 700 Б не идёт «одиночкой» в первые 2 КБ; проверяется эмулятором DPI |
| NFR-10 | Наблюдаемость | метрики: RTT, throughput, retransmits, доля паддинга, причина переключения |
| NFR-11 | Безопасность | TLS 1.3 only, AEAD, forward secrecy, replay-защита, нет логирования SNI/URL |
| NFR-12 | Восстановление | после сна ноутбука/смены сети — reconnect ≤ 3 с без потери приложения |

## 7. Матрица покрытия: тип трафика × путь

Нужна, чтобы не обещать невозможного.

| Тип | Напрямую + анти-DPI | TCP-туннель | QUIC-туннель | Комментарий |
|---|---|---|---|---|
| HTTP(S) браузинг | да (SNI-десинк) | да | да | базовый сценарий |
| Видео (YouTube 4K) | частично (троттлинг CDN) | да (основной) | да, если UDP жив | требует ≥ 40 Мбит/с на поток |
| Голос/видео Discord | нет (нужен релей) | да, с оговоркой по jitter | предпочтительно | TCP-путь даёт head-of-line блокировки: jitter растёт |
| Игры | да (только анти-DPI) | нет | частично | через Хельсинки ping растёт — только direct |
| Bulk-скачивание | — | да | да | главный триггер поведенческого детекта |
| API/gRPC | да | да | да | много мелких записей — самый «палевный» профиль |
| DNS | нет | да | да | только внутри туннеля |
| ICMP/ping | — | нет | нет | не поддерживаем, не обещаем |

## 8. Метрики успеха этапа 1

1. Замерен потолок VPS и канала (iperf3, 30 мин, оба направления).
2. Замерен RTT/потери/джиттер клиент↔HEL по часам суток.
3. Собран эмулятор DPI с 5 правилами (см. `04-lab-plan.md`), проверены 3 кандидата.
4. Принято решение: что именно пишем (v1 scope) и что берём готовым.
5. PRD + SDD прошли ревью владельца, открытые вопросы закрыты.

## 9. Риски

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| VPS-ASN попадёт в списки (поведение/объём) | высокая | высокий | 2+ ендпоинта в разных ASN, ротация, лимит объёма на адрес |
| UDP режут на мобильном | высокая | средний | TCP-путь как основной для голоса, QUIC как ускорение |
| Белые списки на домашнем интернете | средняя | критический | архитектурная сменность ендпоинтов; CDN-фронтинг как опция |
| Перехват TLS (сертификаты Минцифры) | низкая | высокий | второй слой шифрования уже есть (внутренний TLS до сайта не трогаем) |
| Свой протокол = свои баги | высокая | высокий | не пишем крипту; v1 = композиция проверенных примитивов + тесты |
| Правовой риск при распространении | средняя | высокий | приватное использование, без публикации и продажи |
| Датацентровый IP ловит капчу | высокая | средний | опциональный жилой егресс (FR-10) |

## 11. Открытые вопросы

**Закрыты 28.10.2026:**
1. VPS: adminvps, **1 vCPU Skylake 2.3 ГГц**, 1.9 ГБ RAM, порт заявлен ≥1 Гбит/с, диск 82 %, ASN хостера. Измерено: 169/47 Мбит/с через ssh, AES 26 Гбит/с на ядро → **узкое место — 1 ядро** (`05-measurements-2026-10-28.md`).
2. Панель: **3x-ui**, ставим новый демон рядом, профили не трогаем.
3. Платформы: **Windows + Android** (iOS не в v1).
4. Второй ендпоинт: владелец готов, но только если действительно нужно → обоснование в §5 SDD (эвристики 2026), решение отложено до замеров объёма на один IP.
5. Правовой режим: личное использование, без раздачи — принято как допущение.

**Осталось выяснить (блокирует только этап 2):**
1. Реальный потолок канала: нужен `iperf3` на открытом порту (сейчас наружу открыты 22/80/443/10222).
