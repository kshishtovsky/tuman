# 06. Матрица маршрутов: куда с домашней линии едет быстро (28.10.2026)

Домашний ISP: **AS8369 Intersvyaz-2 JSC**, Челябинск (77.222.107.28). Канал заявлен 1 Гбит/с.

Все замеры — HTTP по порту 80, то есть **напрямую, мимо туннеля rupas** (туннель забирает 443). Один TCP-поток, файл 1.4–2.6 ГБ, отсечка 8–10 с, поэтому цифры — установившаяся скорость, а не спидтест.

## 2. Что это доказывает

1. **Порт VPS не при чём.** Один поток до adminvps даёт 117–161 Мбит/с — до заявленного 1 Гбит/с дело не доходит даже близко. Порт 10 Гбит/с на том же маршруте даст те же 161.
2. **Сам VPS здоров.** Он скачивает с MUNI **569 Мбит/с**, с FAU 428, с Leaseweb 274. Значит его аплинк в порядке, проблема — именно путь Челябинск↔Хельсинки-этот-хостинг.
3. **Линия может больше.** В те же минуты с той же линии на Швецию прилетало **685 Мбит/с**, на Чехию стабильно 265+. То есть «250 Мбит/с потолок» — свойство конкретного маршрута, а не канала.
4. **Разброс огромный.** SE: 181 → 685 → 355 за три минуты. Один замер ничего не значит; нужно минимум 3 прогона и медиана.
5. **Швеция и Чехия лучше Финляндии/Нидерландов** с этого ISP. Логика простая: Интерсвязь выходит в Европу через Москву, и дальше всё зависит от того, с кем у транзитного провайдера прямой пиринг.

## 3. Как выбирать хостинг (метод, а не гадание)

### Шаг 1 — бесплатный отсев, без серверов (5 минут)
Гонять большие файлы с публичных зеркал по HTTP/80 в разных странах:

```bash
# пример: один поток, 10 с, покажет установившуюся скорость
curl -sL -o NUL --max-time 10 -w "%{time_connect}s %{speed_download}\n" \
  http://ftp.acc.umu.se/mirror/ubuntu-releases/26.04.1/ubuntu-26.04.1-live-server-amd64.iso
```
Работающие на сегодня зеркала: `ftp.acc.umu.se` (SE), `ftp.fi.muni.cz` (CZ), `ftp.fau.de` (DE), `mirror.leaseweb.net` (NL), `ftp.icm.edu.pl` (PL), `ftp.funet.fi` (FI, 16 МБ файл).
Каждую — 3 раза, брать медиану. Отбираем страны с медианой ≥ 250 Мбит/с.

### Шаг 2 — проверка реального хостинга (1–2 €)
Взять почасовой VPS в 2–3 отобранных локациях (Hetzner, Vultr, DigitalOcean, Scaleway, Aeza — у всех почасовая оплата), прогнать `tools/bin/chan.exe`:

```bash
scp chan_linux user@host:/tmp/chan && ssh user@host 'chmod +x /tmp/chan; sudo ufw allow 8092/tcp; sudo ufw allow 8093/tcp; \
  dd if=/dev/zero of=/tmp/t.bin bs=1M count=200 status=none; \
  setsid -f /tmp/chan serve 8092 /tmp/t.bin >/tmp/s.log 2>&1; \
  setsid -f /tmp/chan sink 8093 >/tmp/k.log 2>&1'
chan.exe get host:8092 200    # вниз
chan.exe push host:8093 200   # вверх
```
Критерий: **≥ 400 Мбит/с вниз одним потоком в 3 прогонах из 3**. Ниже — мимо. Уничтожить сервер.

### Шаг 3 — проверить, что сервер видел домашний IP
В `/tmp/k.log` должен быть source `77.222.107.28`. Иначе замер шёл через туннель и недействителен.

## 4. Про апгрейд adminvps

| Тариф (сайт adminvps) | CPU | RAM | NVMe | Порт | Трафик | Цена |
|---|---|---|---|---|---|---|
| Promo (текущий) | 1 × 3.6 | 2 ГБ | 30 ГБ | до 1 Гбит/с | 3 ТБ/мес | 499 ₽ |
| Micro | 2 × 3.6 | 4 ГБ | 60 ГБ | до 1 Гбит/с | 5 ТБ/мес | 899 ₽ |

- **Для скорости апгрейд бесполезен** — измерено: 161 Мбит/с на потоке, порт не насыщен.
- **Для комфорта полезен**: 2 ядра вместо 1 (панель + туннель + QUIC на одном ядре тесно), 60 ГБ вместо 30 (сейчас занято 82 %, свободно 2.7 ГБ), 5 ТБ вместо 3 ТБ трафика.
- **Трафик — скрытый лимит**: 3 ТБ/мес при 300 Мбит/с выжигаются за ~22 часа. Если планируется видео 4K — Micro (5 ТБ) или тариф с большим лимитом обязателен.
- Если на новом тарифе другой узел/сеть — скорость может измениться. Проверять **до** оплаты: попросить поддержку дать тестовый IP в новой локации и прогнать `chan`.

## 5. Вывод

Скорость определяется маршрутом «Челябинск → датацентр», а не портом, не CPU и не протоколом. Текущий Helsinki-adminvps — плохой маршрут (161 Мбит/с), при том что та же линия даёт 685 в Швецию. Следующий шаг — не апгрейд, а **поиск хостинга с хорошим маршрутом**, ценой 1–2 € на почасовых тестах.
