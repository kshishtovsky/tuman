# Аудит безопасности TMN/1 — 2026-11-02

База: `exp/tmn` @ `9db9287`. Протокол: TLS 1.3 снаружи (`crypto/tls`), внутри собственный
кадровый mux; AUTH = HMAC-SHA256(psk, label‖tls-exporter‖ver‖ts‖nonce), окно `ts ±120 c`.

Аудит вели пять независимых аудиторов (крипто/AUTH, mux-DoS, сервер+деплой, клиент,
docs↔код). **Каждая находка, попавшая в этот документ, перепроверена вручную** —
чтением конкретных строк и, где возможно, прогоном. Находки, которые при проверке
не воспроизвелись, вынесены в §7 и в работу не пошли.

## 2. Критично: контроль приёма (S1, S5, S8)

`deliver` кладёт кадр в очередь потока без сверки с объявленным окном
(`mux/stream.go:346-389`); `recvPending` считается только для того, чтобы вернуть
кредит при сбросе. Верхней границы нет ни у очереди потока, ни у суммы по сессии.

Замер (loopback, окно потока 8 МиБ): в поток залито **192 МиБ**, `HeapAlloc` +282 МиБ.
Одна валидная сессия (ключ есть у любого подписчика) в состоянии уронить сервер всем.
Медленный egress или подвисшее приложение делают это и без злого умысла.

Второй дефект того же узла: `maybeFree` (оба FIN) отдаёт поток без возврата
`recvPending` в `connWin`, а `onStreamClose` — возвращает. Замер: 32 брошенных потока
по 1 МиБ → `connWin = 0`, все `Write` встают намертво, сессия жива и бесполезна.

Третий: `onWU` применяет `int32(delta)` без проверки; `delta = 2^31` делает окно
отрицательным, `reserve` зажимает его в 0, запись висит до прихода честного WU.
`delta` до `2^32-1` наоборот раздувает окно выше буфера пира.

Фикс (один патч): агрегатный `recvTotal` на сессию под `s.mu`, проверка **до** `push`,
общий `returnRecvWindow(st)` для обоих путей закрытия, `int64`-арифметика с клампом
в `onWU`.

## 3. Аутентификация (S2, S15, S17, S18)

Клиент проверяет только `h.Type == TypeAuthOK` и разбирает 12 байт
`ver/maxPayload/windowConn/caps`. Ни тега, ни эха nonce. Сервер, не знающий PSK,
но имеющий доверенный клиенту сертификат (кейс «сертификаты Минцифры» из `docs/03:250`)
или просто клиент с `insecure = true`, отвечает `AUTH_OK` — и получает цели и трафик.

**Проверено запуском:** фейк-пир читает AUTH и отдаёт `MakeAuthOK(...)` без всякого
доказательства; `mux.New(IsClient: true, ...)` возвращает `nil` — сессия установлена.
Утверждение `docs/03:250` «MITM видит только наш шифротекст» неверно.

Второе: `ReplayCache` создаётся внутри `authServer`, т.е. на одну сессию, где AUTH
бывает ровно один раз; `Seen()` не может вернуть `true` никогда. `docs/07:87` и
`docs/03:246` обещают счётчик как защиту — защиты нет (сегодня спасает только
привязка к exporter, см. S7).

Третье: окно `|now-ts| ≤ 120` считается через `d = -d`, и при `ts = now+2^63` модуль
даёт отрицательное число — проверка проходит. **Проверено запуском.**

Четвёртое: `AuthTag` берёт `exporter[:32]`, поэтому exporter из 33 байт даёт тот же
тег, что 32-байтовый с тем же префиксом — тихая потеря энтропии для любого нового
вызывающего (mux сегодня требует ровно 32, но контракт нигде не закреплён).

## 4. Сервер и деплой (S3, S4, S6, S14, S19)

**Egress.** `echo` берёт адрес цели из кадра и диалает его обычным `net.Dialer`
(`cmd/tmns/server.go:245-253`). Резолв происходит в момент dial, поэтому проходят и
`localhost`, и DNS-rebinding. В репозитории уже есть доказательство работоспособности:
`cmd/tmns/tunnel_test.go:20,71` штатно диалает `127.0.0.1`. Цена ошибки — панель на
том же VPS и cloud-metadata (у Hetzner `169.254.169.254` отдаёт SSH-ключи и user-data
без авторизации).

**Логи.** Строка на каждый поток: `"peer", up.RemoteAddr().String()` — это адрес
**цели**, т.е. полная история посещений в journald. Плюс `"detail", err.Error()`, где
текст ошибки dial содержит `host:port`. Документированная проверка в
`deploy/hardening.md:53` (`grep -Ei 'https?://|sni|host:'`) такие строки не ловит.

**Стойкость к флуду.** `limited()` живёт в `fallback`, т.е. уже после TLS-handshake и
после `mux.New` (чтение и HMAC-проверка AUTH). Стоимость попытки — 0.71 мс CPU
(замер на этой машине, Go 1.26.5, ECDSA P-256): один core выедается 1–2 тыс.
соединений/с. Лимита числа соединений нет (`s.conns` — неограниченная map), а любая
ошибка `Accept` завершает процесс — дальше `Restart=on-failure` и `StartLimitBurst=5`.

**ALPN.** Сервер объявляет `["http/1.1","h2"]`, клиент предлагает только `"h2"` →
согласуется `h2`, а первым байтом уходит `08 00 00 00 00 32 00 00` (AUTH-кадр), не
префейс `PRI * HTTP/2.0`. Два независимых признака: несовпадение ALPN с содержимым и
400 в ответ на `curl --http2-only`.

**Секреты.** `loadPSK` не смотрит на права файла; `bytes.TrimSpace` применяется и к
raw-ветке, обрезая ключи, у которых последний байт `0x20/0x0a/0x0d/0x09`.

## 5. Блокер дизайна: uTLS против TLS-exporter (S7)

`NFR-8` и §0 SDD обещают «ClientHello неотличим от браузера». Сегодня клиент —
стоковый Go-TLS: 3 шифра, 11 расширений, без GREASE, без `session_ticket`/`status_request`,
JA3 `771,4865-4866-4867,0-11-65281-23-18-10-13-50-16-43-51,4588-4587-4589-29-23-24-25,0`.
Любое правило «whitelist Chrome/Safari/Firefox» (lab-R2) дропает нас.

Наивное решение «взять `utls.HelloChrome_Auto`» **не работает** и это проверено
запуском, а не рассуждением: браузерные hello содержат расширение `renegotiation_info`,
utls из него выставляет `config.Renegotiation = RenegotiateOnceAsClient`
(`utls@v1.8.2/u_tls_extensions.go:1687`), после чего `ExportKeyingMaterial` возвращает
`crypto/tls: ExportKeyingMaterial is unavailable when renegotiation is enabled`.
Результат прогона (TLS 1.3, self-signed ECDSA P-256, ALPN `h2`):

```
chrome   alpn="http/1.1" match=false cerr=... unavailable when renegotiation is enabled
firefox  alpn="http/1.1" match=false cerr=... unavailable when renegotiation is enabled
safari   alpn="http/1.1" match=false cerr=... unavailable when renegotiation is enabled
golang   alpn="h2"       match=true  cerr=<nil>
```

То есть привязка AUTH к TLS-exporter **и** браузерный отпечаток взаимоисключающи.
Выбор: оставить Go-отпечаток (и потерять D1/NFR-8) или сменить привязку.

**Решение — AUTH v2 (X25519 + MAC), дизайн в `docs/13-plan-v2.md` §3.** Бонусы: привязка
перестаёт зависеть от TLS-стека (работает и с uTLS, и с будущим QUIC), `AUTH_OK` получает
MAC и закрывает S2, replay-кэш становится серверным и осмысленным (S15).

Цена: протокольный разрыв. Клиент и сервер обновляются вместе, старый бинарь с новым
не совместим. Для одного владельца с 1–5 пользователями это приемлемо, но бинарники
предыдущей версии надо оставить для отката.

## 6. Что сделано правильно (не переписывать)

- **Constant-time и порядок проверок AUTH:** `hmac.Equal`, порядок «длина → версия →
  окно → тег», все провалы уходят в сайт-прикрытие без ошибки протокола.
- **Привязка к TLS-сессии реальна** там, где она работает: exporter считается с одного
  label на обеих сторонах, в TLS 1.3 он выводится из свежего ECDHE, resumption у клиента
  не включён — захваченный AUTH на другом соединении бесполезен.
- **Нет downgrade-поверхности:** `ver != 1` → отказ на обеих сторонах, negotiate нет
  by design.
- **Ключевой материал не течёт в ошибки и логи:** ни PSK, ни exporter не попадают ни в
  один `log`/`err.Error()`; `mux.New` отказывается работать при неверных длинах.
- **Отправка уважает окно:** `reserve` берёт `min(sendWin, connWin, MaxPayload)`,
  `release` возвращает кредит при ошибке, `WriteContext` отменяем.
- **Reader не блокируется на отправке** в штатных путях (`trySend` в `consumed`) —
  верное решение, задокументировано в коде.
- **Порядок локов корректен:** единственная вложенность `rmu → s.mu`, обратной нет;
  `-race` чистый.
- **Сайт-прикрытие:** статика в памяти, `http.Server.ErrorLog` выброшен в `io.Discard`,
  `Server` не отдаётся, `Content-Length` всегда точный, `HEAD` без тела.
- **Деплой:** `User=tmn` + одна capability, `ProtectSystem=strict`, `ProtectProc=invisible`,
  `SystemCallFilter=@system-service`, `UMask=0077`; `install.sh` идемпотентен и ничего не
  рестартит; `deploy/.server-tmn.env` никогда не была в истории git.
- **Клиент:** дефолт-действие маршрутизации — `Tunnel`; `suffix()` с проверкой границы
  домена; `Decide` без резолва и без аллокаций; SOCKS-коды и `subtle.ConstantTimeCompare`.

## 7. Отброшено при перепроверке

| Находка аудитора | Почему не пошла в работу |
|---|---|
| «PING-эхо даёт петлю: один вброс → 373 кадра за 500 мс» | Не воспроизводится. Мой прогон: один 8-байтовый PING → ровно один PING в ответ; реальная пара сессий при `PingEvery=10ms` — 47+46 кадров за 600 мс (норма). Амплификации нет. Код всё же пахнет (эхо любого payload, сравнение с текущим nonce), но это косметика, а не дефект — в работу не берём. |
| «Сессия зависает вечно до AUTH» | Отброшено: `shaper.Shaper` реализует `SetDeadline`, `deadliner` в `mux.handshake` срабатывает. |
| «Просто добавить `utls.HelloChrome_Auto`» | Проверено запуском — ломает exporter и всю аутентификацию (§5). |
| «`AUTH_OK.windowConn` перевёрнут, но это работает случайно» | Верно по сути, но это часть v2-разбора AUTH; отдельного фикса не делаем, чтобы не плодить промежуточные форматы. |

## 8. Что не проверено и требует VPS

Живой хост (права на ключ Caddy, `CanReload`, реальные заголовки заглушки), поведение
под настоящим DPI, 2 % потерь (`netem`), восстановление после смены сети/сна, утечка
DNS при живом браузинге. Все цифры выше сняты на loopback — они доказывают дефекты
кода, но не поведение на канале.
