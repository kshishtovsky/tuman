# Т04 — пул клиента: утечка горутины шейпера и джиттер реконнекта

**Severity:** Medium (утечка на каждом неудачном dial; thundering herd после рестарта)
**Репозиторий:** `E:/pet/tuman`
**Слой:** `client` (пул TLS-сессий)

## Зачем

### 1. Шейпер не закрывается при неудачном хендшейке

`client/pool.go:238-245`:

```go
s, err := mux.New(shaper.New(t, shaper.Config{Profile: ...}), mux.Config{...})
if err != nil {
    t.Close()
    return nil, err
}
```

`shaper.New` при профиле ≠ `off` сразу запускает `go s.finish()`
(`shaper/shaper.go:154-159`), который висит на `select { <-s.done; <-s.wake }`
до `Close()`. При ошибке `mux.New` закрывают только TLS-соединение `t`;
`shaper.Close()` не вызывается никогда — горутина и ссылка на мёртвый коннект
живут до конца процесса. Каждый неудачный dial = одна утёкшая горутина.

### 2. Реконнект без джиттера

`client/pool.go:64-75`: сессия, прожившая ≥ 5 c, переподключается через
`t.Reset(0)` — то есть мгновенно. После рестарта сервера все слоты всех
клиентов приходят одновременно (thundering herd), и сервер получает
N×слотов SYN-ов в одну секунду.

## Что менять

Файл: `client/pool.go`.

1. Держать шейпер в переменной и закрывать его на пути ошибки:

```go
sh := shaper.New(t, shaper.Config{Profile: shaper.Profile(c.cfg.Profile)})
s, err := mux.New(sh, mux.Config{...})
if err != nil {
    sh.Close() // закрывает и inner-соединение (closeInner)
    return nil, err
}
```
   Проверить по `shaper/shaper.go:100-160`, что `Close` действительно закрывает
   inner и не паникует при повторном вызове; если закрывает не он — закрыть
   оба (`sh.Close()` + `t.Close()`), лишний `Close` на TLS-conn безопасен.

2. Заменить `t.Reset(0)` на джиттер:
   `t.Reset(rand.N(500 * time.Millisecond))` (`math/rand/v2`).
   Смысл: 0–500 мс разброса при базовой паузе 5 c не ломает SLA «канал оживает
   за секунды», но разводит клиентов.

## Границы

Трогать можно: `client/pool.go`, `client/pool_test.go` (если есть; иначе
создать `client/pool_jitter_test.go`).
Не трогать: `shaper/shaper.go` (если найдётся баг в `Close` — описать в
отчёте, не править), `mux/`, `cmd/`.

## Критерии приёмки

1. `TestPoolShapersDoNotLeak` (новый, `client`): поднять пул против адреса,
   который принимает TCP и молчит (хендшейк падает по таймауту), прогнать 5
   неудачных dial'ов, дождаться завершения: `runtime.NumGoroutine()` до и после
   отличается не более чем на 2. Тест должен падать на текущем коде
   (проверить это, прогнав его до правки) и проходить после.
2. `TestPoolReconnectJitter`: задержка реконнекта попадает в `(0, 1s]` — через
   инъекцию `now`/таймера, если пул это позволяет, иначе — тест на то, что
   `Reset` вызывается с ненулевым аргументом (шов `resetFn` добавить только
   если без него тест невозможен).
3. `go test ./client/ -race -count=1` и `go test ./... -count=1` зелёные.

## Риск

Низкий. Основная опасность — двойное закрытие соединения: `mux.New` при ошибке
уже мог закрыть `conn` (проверить `mux/mux.go:161-167`), поэтому `sh.Close()`
должен быть идемпотентен; если это не так — закрывать шейпер **до** `mux.New`-фейла
невозможно, придётся добавить идемпотентность в `shaper.Close` (тогда это
разрешённая правка `shaper/shaper.go` с тестом).
